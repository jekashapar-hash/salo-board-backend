# 🚀 Workflow: Створення комітів

Використовуйте цей workflow для збереження змін у репозиторій. Коміти повинні бути малими, логічно завершеними та описувати конкретну зміну.

## 📋 Кроки:

1. **Аналіз змінених файлів**
   * Перевірте статус репозиторію: `git status`
   * Перегляньте дифи: `git diff`

2. **Групування змін**
   * Розділіть зміни на логічні частини (наприклад: репозиторії окремо від use cases).
   * Не робіть один гігантський коміт для всього проекту.

3. **Створення коміту**
   * Використовуйте стандарт Conventional Commits українською:
     * `feat:` — нова функція
     * `fix:` — виправлення багу
     * `refactor:` — рефакторинг коду (без зміни функціоналу)
     * `docs:` — оновлення документації
     * `style:` — правки форматування/стилю
     * `chore:` — технічні завдання (залежності, конфіги)
   * // turbo
   * `git add <файли>`
   * `git commit -m "<тип>: <короткий опис українською>"`

4. **Перевірка**
   * Переконайтеся, що коміт створено успішно: `git log -n 1`
